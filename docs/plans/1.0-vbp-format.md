# 1.0 — VBP format

> **Do not invent a `docs/plans/1.0-summary.md` entry for this plan until it is done and archived.**

**Status:** **⏳** proposed  
**Sub-plans:** [`1.1-vbp-writer.md`](1.1-vbp-writer.md) · [`1.2-vbp-parser.md`](1.2-vbp-parser.md)  
**Full mocks:** [`docs/sample.vbp`](../sample.vbp) (Gtk/Vala) · [`docs/sample-roo.vbp`](../sample-roo.vbp) (Roo/JS)

Human-readable alternative to JSON `.bjs`. Grammar owns structure; indentation is cosmetic (2 spaces when writing). Bodies of listeners / methods / `construct` stay **opaque text** (no Vala/JS AST).

This document is **what the file looks like**. Implementation detail lives in 1.1 / 1.2.

---

## File skeleton

```
vbp-version = 1;
name = WindowRooView;
/* optional: parent, title, permname, modOrder, using … */

Gtk.Box WindowRooView {
  orientation = Gtk.Orientation.VERTICAL;
  …
}
```

Roo modules look the same at the top:

```
vbp-version = 1;
name = Pman.Tab.AdminCompanies;
parent = Pman.Tab.Admin;
title = Pman.Tab.AdminCompanies;
permname = Admin.Companies;
modOrder = 030;

Roo.NestedLayoutPanel {
  region = "center";
  title = "Companies";
  …
}
```

- Header is `name = …;` statements (no `path`).
- One root object after the header.
- **🚫** `#` comments in the shell. Use `/** … */` for docs. `//` / `/* */` are fine **inside** code bodies.

---

## Objects and names

```
Gtk.Notebook notebook {
  vexpand = true;
}
```

`Type Name { }` — the Name **is** the author id (codegen `xvala_id`). Do **not** also write `id = "notebook";`.

Anonymous (no id):

```
Gtk.Box {
  orientation = Gtk.Orientation.HORIZONTAL;
}
```

**oid** is runtime-only (undo / DND). **Never** write `oid` into VBP; assign fresh oids on load.

---

## Plain properties

Quoted string → PROP. Unquoted expression → RAW (JS/Vala expression handed to codegen as-is).

```
label = "Preview";
hexpand = true;
orientation = Gtk.Orientation.VERTICAL;
url = baseURL + '/Roo/core_company';
```

Named object property (fills a parent slot — replaces BJS `* prop` / `prop-name` kludge):

```
start_child = Gtk.Box viewbox {
  orientation = Gtk.Orientation.VERTICAL;
}

layout = Roo.BorderLayout {
  center = Roo.LayoutRegion {};
}
```

Array-style slot name (repeatable):

```
colModel[] = Roo.grid.ColumnModel {
  …
};
```

---

## Fields (`var` / access)

```
var Gtk.Widget lastObj = null;
private JsRender.JsRender file = null;
protected Xcls_MainWindow main_window;
```

- `var` = public (preferred).
- `public Type name` = same as `var`.
- `private` / `protected` replace `var` — **🚫** `public var` / `private var`.

---

## Construct (init)

Not an assignment. Keyword + block. Stored as SPECIAL `init` for existing codegen.

```
WebKit.WebView view {
  vexpand = true;

  construct {
    var settings = this.el.get_settings();
    settings.enable_developer_extras = true;
  }
}
```

Ctor expression (which `new` to call) is separate:

```
ctor = new Gtk.Scale.with_range(0, 100, 1);
```

---

## Children lists

Anonymous children: bare `[ … ]`, commas between peers.

```
[
  Gtk.Label label_preview {
    pack = false;
    label = "Preview";
  },
  Gtk.Paned paned {
    pack = append_page, _this.label_preview.el;
    orientation = Gtk.Orientation.VERTICAL;
  }
]
```

---

## Pack

How a child attaches to its parent. Prefer **parent named props** when the slot is a real property (`start_child = …`). Keep child `pack = …;` for opt-out and odd methods.

```
pack = false;
pack = set_start_child;
pack = append_page, _this.label_preview.el;
pack = get_content_area().append;
```

Lean for v1: named parent props first; `pack` only when needed.

## Listeners and methods

Comma between peers. Body text is opaque (Vala or JS depending on project).

**Vala:**

```
listeners [
  clicked () => {
    _this.view.renderJS(true);
  },
  toggled (state) => {
    // …
  }
]

methods [
  void showIt (Gtk.Window? parent) {
    this.el.show();
  }
]
```

**Roo / JS:**

```
listeners [
  rowdblclick (_self, rowIndex, e) {
    _this.dialog.show(…);
  },
  render () {
    _this.grid = this;
  }
]
```

## Documentation

```
/**
 * Preview pane — redraws when the tree changes.
 */
WebKit.WebView view {
  …
}
```

`/** … */` immediately above a node / prop / listener → `doc` on parse. Writer must round-trip it.

## JS expressions and RAW values

### When you do **not** need `@`

Normal expression until `;` (brace/paren depth 0 outside strings). No fence:

```
url = baseURL + '/Roo/core_company';
icon = Roo.rootURL + 'images/default/dd/drop-add.gif';
renderer = function (v) { return v; };
```

`construct { … }` is its own keyword (Vala init) — not this RAW fence.

Quoted PROP strings stay quoted even if they contain `{` (format strings are **not** objects):

```
displayMsg = "{0} - {1} of {2}";
```

### When you **do** need `@` — RHS *is* a `[` or `{` literal

Otherwise the shell thinks you started a child list / object / opaque block.

Corpus (JS round-trip originals, ~1250 hits; almost all `node-type` RAW):

| Prop | Shape | Typical |
|--|--|--|
| `fields` | `@[ … ]` | ~600 — often multiline (reader field lists) |
| `sortInfo` | `@{ … }` | ~500 — almost always one line |
| `data` | `@[ … ]` | ~80 — option lists, often multiline |
| `baseParams` | `@{ … }` | ~14 — single or few lines |
| `css_classes` / `styles` / `autoCreate` / `authors` / `loadMask` / `white` / `stylesheets` / `colItems` / `builderCfg` | `@[` or `@{` | handful each |
| legacy `\|fields` / `\|sortInfo` / `\|baseParams` | same | rare |

Vala tree also has a few `{`-starting `init` bodies — those map to **`construct { }`**, not `@`.

### Lean fence: `@` + `[` or `{`

Same nesting rules as today for `[` `]` / `{` `}`; `@` only means “this group is a RAW value, not VBP structure.” Close the group, then `;`.

**Single-line object:**

```
sortInfo = @{ field : 'event_when', direction: 'DESC' };
```

**Multiline object** (newline after `{` fine):

```
baseParams = @{
    '_import_activity': 1,
    '_confirm_direction': 0
};
```

**Array** (the big `fields` case):

```
fields = @[
    { name: 'code', type: 'string' },
    { name: 'name', type: 'string' },
    { name: 'id', type: 'int' }
];
```

- **🔷** `@[` … `]` / `@{` … `}` → `NodePropType.RAW`; payload is the `[…]` / `{…}` text (include the brackets/braces).
- **🔷** Writer: if RAW value strips to start with `[` or `{`, emit with leading `@` (keep newlines inside).
- **🔷** Parser: after `=`, if `@` then `{` or `[`, parse one nested group as opaque RAW, expect `;`.
- **🚫** Do not quote these as shell strings (`fields = "[…"`) — that was a tokenizer workaround and breaks codegen.
- **🚫** `@"""` — dropped in favour of `@[` / `@{` (same job, less new delimiter).
- **💩** Writer: also `@`-prefix other RAW that would confuse the shell? (Probably not if it doesn’t start with `[` `{`.)
- **💩** Accept bare `fields = [ … ];` without `@` for hand edits? Safer writer always emits `@`.

## Translatable strings (Roo)

Author the plain text as a normal quoted PROP:

```
loadingText = "Searching...";
emptyMsg = "No Companies found";
```

Codegen (unchanged idea): names in `doubleStringProps` → `_this._strings['«md5»'] /* Searching... */` plus a `_strings` map in the generated file. Translation extract historically walks BJS plain strings.

**Wrong today:** `loadingText = Searching...;` (unquoted) → treated as RAW → no `_strings`.

## Tiny complete examples

### Gtk fragment

```
vbp-version = 1;
name = Demo;

Gtk.Box root {
  orientation = Gtk.Orientation.VERTICAL;

  var int redraws = 0;

  [
    Gtk.Button go {
      label = "Redraw";
      listeners [
        clicked () => {
          _this.view.renderJS(true);
        }
      ]
    }
  ]

  methods [
    void ping () {
      this.redraws++;
    }
  ]
}
```

### Roo fragment

```
vbp-version = 1;
name = Pman.Demo;

Roo.grid.Grid grid {
  autoExpandColumn = "name";
  loadMask = true;

  dataSource = Roo.data.Store {
    remoteSort = true;
    sortInfo = @{ field: 'name', direction: 'ASC' };

    proxy = Roo.data.HttpProxy {
      url = baseURL + '/Roo/core_company';
      method = "GET";
    }

    reader = Roo.data.JsonReader {
      fields = @[
          { name: 'code', type: 'string' },
          { name: 'id', type: 'int' }
      ];
    }
  }
}
```

## Mapping cheat sheet (file → memory)

| You write | In-memory |
|--|--|
| `Type` / `Type Name { }` | OBJECT (+ `id` prop from Name) |
| `name = "…";` | PROP |
| `name = expr;` (unquoted, no `@`) | RAW (urls, `function…`, etc.) |
| `name = @{ … };` / `name = @[ … ];` | RAW (object/array literals) |
| `prop = Type Name { }` | child OBJECT with `prop_name` |
| `var` / `public` / `private` / `protected` | USER |
| `pack` / `ctor` / `args` | SPECIAL |
| `construct { }` | SPECIAL `init` |
| `listeners [ ]` peers | LISTENER |
| `methods [ ]` peers | METHOD |
| bare `[ ]` | anonymous OBJECT children |

Same shell for Gtk and Roo; project `xtype` picks codegen.

## Open points (short)

### RAW fence 💩→ lean `@[` / `@{`

See **JS expressions and RAW values**. Scope ≈ RAW values whose text starts with `[` or `{` (`fields`, `sortInfo`, `data`, …). Syntax: `@[ … ];` / `@{ … };` (single- or multiline). Drop `@"""` / `{{{ }}}`.

### Strings header 💩

Optional later:

```
strings {
  "1243daf593…" = "Searching...";
}
```

Load could inject/validate; write could emit after generate. Decide: **translator source of truth** (PROP becomes a checksum ref) vs **derived cache** (plain quoted PROP stays canonical; header optional). If extract stays on BJS, fixing quotes may be enough.

### Pack long-term 💩

v1 = named parent props + child `pack` for exceptions. Later: opt-out-only on child once notebook/dialog attach has a parent-side spelling.

### Misc 💩

- Trailing commas in `[ ]`?
- `;` after `prop = Type { }`?
- `using Gtk 4.0` — store or ignore?
- `dialect = vala|js` header vs infer from project?
- Rare SPECIAL escape (`columns`, `response_id`, `xinclude`) — keyword later or `special name = …` hatch?

## What we are replacing (BJS pain)

JSON `.bjs` with numeric `node-type`, `$` / `|` / `*` markers, and named props stuffed into `children` via `prop-name`. VBP keeps the same in-memory tree; only the file text changes.

Load `.bjs` forever until migration is explicit. Writer CLI: `--test-write-vbp` (see 1.1). Parser: 1.2.
