## Purpose

- **🔷** Parse `.vbp` → the **same** in-memory model as BJS v3 (`JsRender.Node` / `NodeProp` / `NodePropType`).
- **🔷** **PHP reference parsers first** (algorithm source of truth for the Vala port):
  - tokenizer (lex + nest) → structural pass
  - same two stages as Vala
- **🔷** Pipeline (easier than one giant recursive-descent “full lexer+parser”):
  1. **Tokenizer** — string-aware scan; `{ }` / `[ ]` nested via stack (no second tree pass)
  2. **Structural pass** — walk the tree → file metadata + `Node` tree
- **🔷** Code / listener / method / `construct` bodies stay **opaque text** (collapse to one blob), same as BJS `prop_val`.
- **🔷** Indentation is **visual only** — parser ignores whitespace runs except as token separators.
- **🚫** Full Vala/JS AST / language server in this phase.
- **🚫** Hooking product load/save as default yet (CLI test first, like Writer).

## Why two stages (not one “full lexer”)

- **🔷** String-aware **tokenize + nest** in one pass stops braces inside `"…"` / `'…'` / Vala `"""…"""` from faking structure, and builds the `{ }` / `[ ]` tree while scanning (PHP `parseTree` / Vala `parse_tree` — no second tree walk).
- **🔷** Structural pass only understands the **VBP shell** (`Type Name { }`, `name = …;`, `var` / `public` / `private` / `protected …;`, `listeners [ ]`, `methods [ ]`, bare `[ ]`, `construct { }`).
- **🔷** Bodies are then **joined token text** stored in `prop_val` — no language parse.
- **ℹ️** Matches parent **1.0** “Lexer then structural parse”; the “tree” is the tokenizer’s output, not a separate stage.

```
.vbp stream
   │
   ▼
 Tokenizer  ──►  Token tree     (lex + nest `{ }` / `[ ]` in one pass)
   │
   ▼
 Structural ──►  JsRender.JsRender + Node / NodeProp tree
```

## Layout and types

- **🔷** `⏳` Folder: keep `src/Vbp/`
- **🔷** `✔️` Files (names locked for this phase):

  - `src/Vbp/Parser.vala` — tree → `JsRender.JsRender` / `Node` **✔️**
- **🔷** Namespace: **`Vbp`**
- **🔷** Meson: `Token.vala` + `Tokenizer.vala` + `Parser.vala` beside `Writer.vala`.
- **🔷** Approved public entry for this phase:
  - **`public class Parser`** **✔️**
  - **`public void parse_into(JsRender.JsRender file, GLib.InputStream input) throws GLib.Error`** — sets `file.tree` + header fields (`name`, `parent`, …)
  - **`public JsRender.Node? parse(GLib.InputStream input, JsRender.JsRender? file = null)`** — root object (CLI dump)
- **🔷** Internal (🔷-named; do not add more without plan edit):
  - **`Tokenizer(GLib.InputStream input)`** — file, `MemoryInputStream`, or any stream
  - **`Tokenizer.parse_tree()`** → root `Token` (kind `[]`; lex + nest in one pass)
  - **`Tokenizer.tokenize()`** → flat `Gee.ArrayList<Token>` (includes comments)
  - **`Parser` walks `Token`** (private walk methods only if named in a later revision; prefer one `parse_into` + few **🔷** private steps: `parse_header`, `parse_object`, `parse_list`)

### Token kinds (locked to PHP)

- **🔷** Structural singles: kind **is the character** — `{` `}` `[` `]` `=` `;` `,`
- **🔷** Groups in the tree: `{}` and `[]` (openers `{` / `[` become a group node; closers pop)
- **🔷** Opaque: `TEXT` (idents, numbers, strings with delimiters kept, `=>` split as `=` + `TEXT`)
- **🔷** Comments: `//` and `/*` on the flat stream; **skipped from the tree**
- **🔷** Keywords are `TEXT` idents checked by spelling: `var`, `public`, `private`, `protected`, `construct`, `listeners`, `methods`, `pack`, `ctor`, `args`, …
- **🚫** Separate `IDENT` / `STRING` / `LBRACE` kinds — PHP did not split them; Vala must not invent a second grammar.

### Token (tree node)

- **🔷** One type: `kind`, `text`, `children` (`Gee.ArrayList<Token>` — same nesting role as `JsRender.NodeBase.children`).
- **🔷** Leaf = empty children; group = `{}` / `[]` with nested children.
- **🔷** Parens stay inside `TEXT` / sibling `TEXT` for v1 (not a group).

## Stage 1 — Tokenizer

- **🔷** Scan with an explicit **string / comment state** (not regex-only brace matching).
- **🔷** Shell string forms: at least `"…"` with `\`; **💩** `'…'` in shell.
- **🔷** Inside opaque bodies we still tokenize strings so nested `{` in strings do not break the **token tree**; body text is reconstructed later from token range.
- **🔷** PHP reference: track source offset on tokens (for opaque body slices + errors). Line/col **💩** optional in Vala port.
- **🚫** Indent tokens as structure.
- **🚫** Full Vala/JS keyword tables beyond VBP shell keywords.

## Stage 2 — Token tree

- **🔷** Walk flat tokens; push/pop on `{` `[` / `}` `]`.
- **🔷** Mismatch / leftover open → hard error with position.
- **🔷** Result: root list of header statements + top-level object group(s).
- **🔷** Commas / semicolons / idents remain **siblings** inside a group (structural pass interprets them).

---

## Stage 3 — Structural pass → Node

Map using parent **1.0** kind rules (locked spellings from Writer):

| VBP shape | In-memory |
|-----------|-----------|
| `Type` / `Type Name { … }` | `OBJECT`; `prop_type` = FQN; `id` prop if Name present |
| `name = value;` (plain) | `PROP` or `RAW` (expression heuristic **💩**) |
| `var Type name = value;` / `var Type name;` | `USER` public |
| `public Type name = …;` | `USER` public (same as `var`) |
| `private Type name = …;` / `protected Type name = …;` | `USER` with that access |
| `pack` / `ctor` / `args` = … | `SPECIAL` |
| `construct { … }` | `SPECIAL` name `init`, body → `prop_val` |
| `listeners [ peer, peer ]` | each peer → `LISTENER` |
| `methods [ peer, peer ]` | each peer → `METHOD` |
| bare `[ obj, obj ]` | anonymous `OBJECT` children |
| `prop = Type Name { … }` | child `OBJECT` with `prop_name` set |
| `/** … */` above item | → `doc` |

- **🔷** Header: `vbp-version`, `name`, `parent`, `title`, `permname`, `modOrder` → `JsRender` fields (skip unknown **💩** / `using`).
- **🔷** Assign oids via existing file node registration patterns (same as BJS load).
- **🔷** Listener peer shape: `name` + opaque remainder (signature + body text).
- **🔷** Method peer shape: optional return type + `name` + opaque remainder.

---

## Opaque body collapse

- **🔷** When structural pass expects a code/expression body:
  - Take the token subsequence (often a `BRACE_GROUP` or tokens until `;` at depth 0 inside current group)
  - Join original source slice → `prop_val`
- **🔷** Do **not** interpret Vala/JS inside.
- **💩** Exact whitespace preservation vs trim — prefer preserve slice from first to last token offset.
