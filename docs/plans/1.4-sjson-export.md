## Purpose

- **🔷** Ship `.sjson` on Roo save and alongside `--test-write-vbp`.
- **🔷** Serializable catalog types under namespace **`JsRender.Sjson`**, **one class per file**.
- **🔷** Conversion is **`JsRender.Sjson.FromNode`**: visit the in-memory tree, **return** a populated root object.
- **🔷** Caller owns I/O — `Json.gobject_serialize(doc)` + `Json.Generator` + `writeFile`. **🚫** hand-built `Json.Object` / `set_*_member` for catalog output.

- **🚫** Profusion of tiny one-line private helpers (`prop_text`, `first_table`, `tab_path`, …) — inline at the visit site or keep logic in the approved type methods below.

- **🔷** Regex literals at use site for fixed patterns — **🚫** try/catch around them.
- **🔷** `switch` on fqn / xtype — **🚫** if-chains for dispatch.

## Catalog version

There is **one** version field on the root document: **`format: 2`**. That is the **catalog schema version** for this sidecar — not BJS v3, not a separate “wire format 3/4”. It means “this JSON follows the Phase 5 group shape (`forms[]` / `grids[]` / `tabs[]`).”

**🔷** Always emit `"format": 2` in output — **✔️** forced in `Document.serialize_property` (`case "format"`).

Bump to `3` only if we break the group shape later.

## JSON keys (locked)

What actually appears in `.sjson` from `Json.gobject_serialize` (GObject property names):

| Meaning | JSON key | Values |
|---------|----------|--------|
| Catalog schema version | `format` | `2` |
| Translation md5 → text | `strings` | object |
| Label key → md5 | `named-strings` | object (GObject hyphenates `named_strings`) |
| Form field widget class | `xtype` | `TextField`, `ComboBox`, … |
| Tab content shape | `xtype` | `form`, `grid`, `mixed` |
| Module header | `modOrder`, `name`, … | as today |

**🔷** PHP readers use **`named-strings`** (hyphen), not `named_strings`. No rename fight with GObject.

**🔷** Use **`xtype`** everywhere we mean “kind of widget” or “kind of tab” — **🚫** separate JSON keys `type` / `kind`. (Older **1.3** example JSON still shows `type`; update examples when editing **1.3**.)

## Serializable types (one file each)

Each: `public class … : GLib.Object, Json.Serializable`

Same quartet as `NodeBase` / `JsRender`:

- `set_property` / `get_property` → `base`
- `find_property`
- `serialize_property` — custom arms for `Gee.HashMap` / `Gee.ArrayList`; **🚫** rely on default serializer for HashMap (json-glib logs `Unsupported type 'GeeMap'` and emits garbage like `{ "size": 7 }`)
- `deserialize_property` — enough for round-trip tests 💩

**HashMap note:** types are `Gee.HashMap<string,string>`. Json-glib’s internal name for that GType is `GeeMap` — that is **not** a separate type to use; it means the default serializer was invoked instead of your `serialize_property` arm (usually a **property_name mismatch**, e.g. switch case `named_strings` vs GObject name `named-strings`).

### **🔷** `JsRender.Sjson.Field`

- `name`, `label`, `xtype` — strings, default `""`

### **🔷** `JsRender.Sjson.Form`

- `table` — string
- `lookups` — `Gee.ArrayList<string>` (HttpProxy tables under the form)
- `fields` — `Gee.ArrayList<Field>`

### **🔷** `JsRender.Sjson.Col`

- `dataIndex`, `header`, `width` — strings

### **🔷** `JsRender.Sjson.Grid`

- `table` — string
- `cols` — `Gee.ArrayList<Col>`

### **🔷** `JsRender.Sjson.Tab`

- `path`, `title`, `xtype` — strings (`xtype`: `"form"` \| `"grid"` \| `"mixed"`)
- `forms` — `Gee.ArrayList<Form>`
- `grids` — `Gee.ArrayList<Grid>`

### **🔷** `JsRender.Sjson.Document` (root)

- `format` — `int`, default `2`
- `name`, `parent`, `modOrder`, `permname`, `title` — strings
- `strings` — `Gee.HashMap<string,string>` (md5 → text)
- `named_strings` — `Gee.HashMap<string,string>`
- `forms`, `grids`, `tabs` — `Gee.ArrayList<…>`

**HashMap → JSON object** and **ArrayList → JSON array**: custom arms in `Document` / `Form` / `Grid` / `Tab` `serialize_property` (same pattern as `NodeBase.children` / `Symbol`). Match **`property_name` as passed by json-glib** (GObject names — often hyphenated).

**Approved on Document:**

- **`Document(JsRender file)`** — copy header + translation maps from file
- **`visit_node`**

**🚫** No `fill_from`, `to_node`, `write()`, or `path_for()` on these types.

## Conversion — **🔷** `JsRender.Sjson.FromNode`

Visitor / tree walk. Pattern close to `NodeToJs` / `NodeToVala`: hold file + working document, walk nodes, return the document.

### Construction / entry

```vala
/**
 * Build a catalog Document by visiting the file tree.
 *
 * Caller must have run findTransStrings. Caller serializes and writes.
 *
 * == Example ==
 *
 * {{{
 *   file.findTransStrings(file.tree);
 *   var doc = new JsRender.Sjson.FromNode(file).munge();
 *   size_t length;
 *   gen.set_root(Json.gobject_serialize(doc));
 *   file.writeFile(sjson_path, gen.to_data(out length));
 * }}}
 */
public class FromNode : GLib.Object
{
	JsRender.JsRender file;

	public FromNode(JsRender.JsRender file) { … }

	/** Visit tree; return populated Document. */
	public Document munge() { … }
}
```

### Approved methods

| Class | Methods |
|-------|---------|
| **FromNode** | `munge()` |
| **Document** | `Document(file)`, `visit_node` |
| **Context** | properties only — `new Context() { doc = …, forms = …, grids = … }` |
| **Field** | `collect_from_node` |
| **Col** | `from_node` |
| **Form** | `from_node`, `process_node` (instance) |
| **Grid** | `from_node`, `is_grid_node` |
| **Tab** | `collect_from_tree`, `from_panel` |

**🚫** No further walk helpers on `FromNode`.

Tab vs flat (locked):

- Tabs found → populate **`doc.tabs` only** (AdminPerson).
- Else → **`visit(root)`** fills **`doc.forms` / `doc.grids`**; **`doc.tabs` empty** (AdminAddIpv6).

### Visit rules (inline in `visit` / `visit_form` / `visit_grid` — not separate helpers)

- `Roo.form.Form` → `visit_form`; **stop descending** that form as another top-level form.
- `Roo.GridPanel` / `Roo.Grid` → `visit_grid`.
- Under a form: `Roo.data.HttpProxy` → lookup table; `Roo.form.*` fields → `Field` (ComboBox / MoneyField extras match PHP: `hiddenName`, `currencyName`).
- Field `type` = xtype after `Roo.form.` strip.
- Labels: prefer `named_strings` → `strings` resolution, else prop `fieldLabel`, else name — **inline** in `visit_form`.
- Table from `/Roo/{table}` url — **inline** regex / match at use site.
- Prop value from child — use existing `node.get_prop(…)` at use site.
- **🚫** No `fieldDetails` map, flat `urls[]`, or name-only field lists.

Detection reference: `Bjs.php` `walkTreeV3` / tab-region helpers. Output nesting follows **1.3** Examples B–D, not PHP’s tab `fields` / `relatedTables` bag.

**Grid detection (aligned with PHP scope walk):**

- Treat **`Roo.GridPanel`**, **`Roo.Grid`**, **`Roo.panel.Grid`**, **`Roo.grid.Grid`** as one grid group (AdminPerson “System Settings” / “User Sessions” use panel/grid wrappers, not `tableName` on GridPanel).
- Resolve **`grids[].table`** from `tableName`, then grid `url`, then first **`Roo.data.HttpProxy`** `url` in the grid subtree (relative search — same tables PHP puts in tab `relatedTables`).
- **🚫** Still no synthetic `forms[]` entry for grid HttpProxy; table lands on **`grids[].table`**, cols on **`grids[].cols[]`**.

## Wiring

### Path

Caller computes sibling path (same as VBP / JS):

```vala
var js = file.targetName();
var sjson_path = js.has_suffix(".js")
	? js.substring(0, js.length - 3) + ".sjson"
	: js + ".sjson";
```

Inline at call sites — **🚫** no path helper type.

### Roo.save()

After `findTransStrings` / `saveBJS`, with tree present:

```vala
var doc = new JsRender.Sjson.FromNode(this).munge();
var gen = new Json.Generator();
gen.pretty = true;
gen.indent = 2;
gen.set_root(Json.gobject_serialize(doc));
size_t length;
this.writeFile(sjson_path, gen.to_data(out length));
```

### `--test-write-vbp`

After load + VBP write: reset / `findTransStrings`, then same `FromNode` + `writeFile` for `.sjson`; print both paths.
