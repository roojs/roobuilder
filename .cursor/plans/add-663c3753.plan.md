# Fix async checkbox visibility and add to PopoverAddProp

## Problem

1. In `PopoverProperty.bjs`, the `is_async` checkbox visibility is only set 
during `show()`. For user-defined types, the type dropdown (`ptype`) may
still be updating, so visibility can be wrong until the user interacts.
2. `PopoverAddProp.bjs` lacks async support entirely when adding METHOD 
properties for Vala.

## Solution

### 1) PopoverProperty.bjs — correct timing and dynamic updates

- Recompute `is_async` visibility after `ptype.setValue(...)` in `show()`.
Use an idle callback to run after the selection has settled.
- Also recompute in the `ptype` `notify["selected"]` handler so changes 
while the dialog is open immediately update visibility.
- Visibility rule: `(ptype == METHOD) && (file.language == "vala")`.

### 2) PopoverAddProp.bjs — add native async checkbox

- Add a `Gtk.CheckButton` labeled "Async" (no extra label). Place it in 
the header/controls area.
- Visibility rule: based on the currently selected property in the list: 
`(selected.node_type == METHOD) && (file.language == "vala")`.
- When double-clicking to add a property, if the checkbox is visible, 
call `prop.modify_is_async(check.active)` before running `Action.Add`.
- Update checkbox visibility/state on:
- selection changes in the list
- initial `show(...)` with the incoming `ptype`

## Files to modify

- `src/Builder4/PopoverProperty.bjs`: add recompute calls after 
`ptype.setValue(...)` (via idle) and in `notify["selected"]` handler.
- `src/Builder4/PopoverAddProp.bjs`: add `is_async` `Gtk.CheckButton`; 
wire visibility + apply flag on add.

## Testing

- Edit an existing property: switching ptype to METHOD shows the async 
checkbox; switching away hides it.
- For user-defined properties shown via `show()`, async visibility is 
correct immediately (no manual interaction needed).
- In Add Property popover, selecting a METHOD in a Vala file shows the 
async checkbox; adding applies the flag to the new prop.
- In JS files or non-METHOD props, checkbox remains hidden.
