# CLI node actions simulation with original OID mapping

## Scope

Add CLI flags (all prefixed with `--action-`) to perform node-level actions within a BJS file using OIDs or JSON payloads. Handle OID remapping from original file OIDs to current in-memory OIDs. After any action, save the BJS and write generated outputs automatically.

## Files to update

- `src/Application.vala`: add flags, parse/validate, dispatch actions, save and generate outputs
- `src/JsRender/NodeBase.vala`: add `oid_orig` field; serialize/deserialize it; store original OID during load
- `src/JsRender/JsRender.vala`: add `orig_oid_to_cur(int orig_oid)` method to map original OIDs to current OIDs

## Flags (all action-prefixed)

- Common:
- `--project <NAME|PATH>`
- `--file <REL_PATH>`: target BJS file
- Exactly one action per run

- Actions (value-accepting, not booleans):
- `--action-move <OID>`: move node (OID can be original from file)
- `--action-copy <OID>`: copy node (OID can be original from file)
- `--action-add <JSON>`: add new node from JSON
- `--action-changeprop <JSON>`: JSON must include `oid` (can be original) and property fields

- Destinations for move/copy/add (choose exactly one when required):
ন  - `--action-to-parent <OID>`: destination parent (OID can be original)
- `--action-to-before <OID>`: place before this sibling (OID can be original)
- `--action-to-after <OID>`: place after this sibling (OID can be original)

## OID mapping implementation

1. Add `oid_orig` to `NodeBase`:

- Property `int oid_orig { get; set; default = -1; }`
- Serialize if `oid_orig != -1`
- Deserialize and preserve during load

2. Store original during deserialization:

- In `NodeBase.deserialize_property` for "oid", also set `oid_orig` if present
- If `oid` is missing or default, `oid_orig` remains -1

3. Add mapping method in `JsRender`:

- `public int orig_oid_to_cur(int orig_oid)`: walk `file.tree` recursively, match `oid_orig`, return current `oid`; return -1 if not found
- Used by CLI handlers to resolve OIDs before actions

## Behavior

1. Parse options; ensure mutual exclusivity.
2. Load projects; resolve `--project` and `--file`; load BJS; ensure `file.tree` is ready.
3. Resolve OIDs using mapping:

- For `--action-move`, `--action-copy`, `--action-to-*`: map original OIDs via `orig_oid_to_cur()`
- For `--action-changeprop`: extract `oid` from JSON, map if needed
- Error if mapping returns -1

4. Execute action (use mapped current OIDs):

- copy: `Action.Add.from_node(file, srcNode, destParent, index).run()`
- move: `Action.Move(srcNode, destParent, index).run()`
- add: `Action.Add(file, json, destParentOrNull, isNode, index).run()`
- changeprop: map JSON fields to `Action.ChangeProp` setters and `run()`

5. Validate and `file.save()`; write generated outputs.
6. Print success; non-zero exit on errors.

## Examples

- Move using original OID 5 to parent with original OID 10:
- `roobuilder --project MyApp --file src/ui/MainWindow.bjs --action-move 5 --action-to-parent 10`
- Change properties using original OID 7:
- `roobuilder --project MyApp --file src/ui/MainWindow.bjs --action-changeprop '{"oid":7,"prop_val":"OK"}'`
